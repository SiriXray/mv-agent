# MV Agent 音乐影像工作台

本地运行的单人 MV 创作平台：上传歌曲和参考图片，规划、编辑分镜，调用视频模型，查看逐镜进度并导出保留原曲的 MP4。

> 当前实现是本机单用户工作台，不是已部署的公网或团队服务。不要直接开放 5410 端口。仓库不包含密钥、歌曲、参考素材、生成视频或本地任务数据库。

## 功能

- 原曲上传与波形；支持 LRC、SRT、VTT，纯文本歌词仅提供估算时间。
- 图片描述与 LLM 分镜规划：支持配置独立连接，调用前确认费用。
- 可变剪辑镜长；新项目默认每镜申请15秒上游素材、2K输出，剪辑并非等长拼接。
- 视频适配器：Q4 Preview、Wan 3.0 文生、Wan 2.1 图生、MiniMax H3。缺少完整协议的模型保持禁用。
- 创作工作台及项目卡片显示计划、历史受理、成功、失败、创建不明和未提交数量。
- 分镜明细可看素材、实际提示词、模型、上游ID、尝试次数、失败原因和请求历史。
- 单镜修改提示词后付费重提：另建生成版本，复用其他成功素材，不覆盖旧版本。
- 每次单镜修订最多创建一次；未知请求需要独立重复计费确认，响应丢失后按原幂等键核对。
- 校准成片与留黑版按导出回执展示，各自保留成功镜数、时间和缺口。
- 单任务并发1–5；显式授权最多同时运行两部作品，共享5路上游请求和2路本地媒体工作。
- 去除模型声音、保留原曲；校验分辨率、双轨起点和尾差，并支持原曲首中尾相关性验收。

规格验收不等于人物一致性、口型、逐字歌词或审美验收，内容仍需人工检查。

## 本地启动

需要 Node.js 22+（当前验证使用 Node.js 24）、FFmpeg 和 ffprobe。应用无第三方 npm 运行依赖。

```sh
git clone https://github.com/SiriXray/mv-agent.git
cd mv-agent
node --version
ffmpeg -version
ffprobe -version
npm start
```

打开 [http://127.0.0.1:5410](http://127.0.0.1:5410)。私有仓库克隆需要 GitHub 授权。
首次启动会自动创建被 Git 忽略的 `data/`；不会恢复历史任务或自动发起付费生成。

### 配置模型

如需通过环境变量配置，首次复制模板；不要覆盖已有 `.env`：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

Linux/macOS 可用 `test -f .env || cp .env.example .env`。

- 视频密钥只填写需要使用的供应商字段；Q4 Preview 使用独立的 `VIDU_PREVIEW_API_KEY`。
- 真实视频调用还需要 `ENABLE_LIVE_GENERATION=true` 和界面费用确认。
- 在“配置”页面设置规划、识图连接；完整接口URL、协议与模型应匹配实际供应商。
- 页面保存的AI配置写入 `data/ai-settings.json`，优先于环境初始值；该文件含敏感配置，不得提交到Git。
- 程序代码更新需重启。视频凭证可在没有生成任务时通过界面的重新读取功能加载。
- API可用性、价格、权限和模型限制以供应商当前规则为准；不要将示例配置视为已经联调。

## 安全执行边界

任务使用不可变快照。修改当前项目脚本不会偷偷改变已提交任务；“修改提示词并重提”明确创建新生成版本。

创建超时、5xx或缺少上游ID不等于失败。系统保留未知请求并停止后续派发，不盲目重发。
已有上游ID的未完成任务须先核对，不重复创建。单镜重提不会恢复已作废任务，也不会从过期生成版本继续派发。
停止本地执行不保证取消供应商任务或退款。

普通生成模式可能按已确认的重试和后备设置继续尝试；批量补交与单镜修订限定本轮每镜最多一次新创建。
模型调用、重试和后备均可能计费，平台没有独立的账户扣费或退款系统。

## 独立导出

先在分镜明细中取得任务ID，确认任务已停止且没有其他媒体导出，再逐部串行执行：

```sh
# 全镜成功且已有组装文件：验证或校准原曲时间轴
node --env-file-if-exists=.env tools/finalize-mv.mjs <job-id>

# 明确接受缺镜留黑：保留原时间槽和完整原曲
node --env-file-if-exists=.env tools/export-gap-draft.mjs <job-id> --allow-gaps
```

CLI只读数据库，不调用模型；写入新UUID文件，不覆盖旧成片。回执位于 `data/work/<job-id>/`。
相同素材的重复执行会验证并复用已导出文件。锁冲突、回执不一致或校准失败时先核查进程和记录，不自动删锁或反复导出。
留黑版不是全镜成功版本；缺镜CSV和时间轴清单与回执一同保存。

## 验证

```sh
npm test
node --check server.mjs
node --check public/app.js
```

单元及HTTP集成测试使用隔离目录与测试供应商，不使用生产密钥或真实模型额度。
`npm test` 按文件串行运行，减少媒体测试并发压力。

浏览器测试另需 Playwright 和 Chromium：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:e2e
npm run test:ai
npm run test:concurrency
npm run test:shots
```

也可用 `MV_PLAYWRIGHT_MODULE` 指向既有Playwright安装。运行器优先使用显式配置、项目安装，最后尝试可用的本机Codex依赖。
报告和截图写入被忽略的 `artifacts/`。浏览器测试请逐条执行，避免媒体工作并发叠加。

`node tools/test-live-frontend.mjs` 是可选的本机只读验收：要求已有正在运行的工作台和项目，拦截写请求，不用于全新空仓库。

提交前可执行 `npm run check:repository`，检查Git暂存文件范围、常见凭据格式和当前本机已知密钥是否混入。此检查不打印密钥，也不能代替人工审阅。

## 上云前的边界

当前服务只监听本机，并校验Host、Origin和本地会话令牌；这个令牌不是用户登录系统。
云服务器费用之外，还需考虑模型调用、媒体存储及下载流量，但本仓库尚未实现OSS或公网部署配置。

公网或团队版需先补齐登录、项目权限、HTTPS、可信代理边界、费用额度与审计、备份恢复和任务持久执行。
当前 `data/store.json` 只允许一个服务进程写入；不要由本机和服务器同时派发同一份任务。
多人协作需要迁移数据存储与执行机制，不能直接复制单用户版本当作已完成的团队服务。

2K转码对CPU、内存和磁盘要求较高，需要在目标机器实测。原曲、参考图和生成内容应具有所需使用权。
仓库上传不等于网站已经上线；不要把 `.env` 或 `data/` 放到GitHub Pages。

## 目录

- `server.mjs`：本机HTTP API与静态文件服务。
- `lib/`：分镜、供应商、任务执行、版本、媒体处理及验收。
- `public/`：中文响应式工作台。
- `tests/`：隔离单元及集成测试。
- `tools/`：导出CLI、浏览器回归与仓库检查。
- `.env.example`：不含凭据的配置模板。

本仓库仅包含实现和必要文档。原曲、参考图、成片、本机数据库、历史操作说明、研究附件、设计快照和测试产物留在本机，不随Git提交。
